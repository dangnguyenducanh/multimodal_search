# Phase 5: Adding images to the reranker

**Goal:** the project's core question. Does the product photo improve a strong text reranker?
**Baseline:** the ZR run from [0.md](0.md) (text only), and our best text model from [4.md](4.md).
**Sources:** SQID paper (arXiv 2405.15190: CLIP text 0.8107, CLIP image 0.8225, text+image score fusion ≈ +2.4% over
CLIP text) · Crossing Minds, "Captions Are Worth a Thousand Words" (arXiv 2402.08532: image captions as extra text on
ESCI Task 1) · [ZR] `RobertaWithSampleWeight_Bag.py` (the slot where side embeddings join [CLS]) · ETS-Lab KDD paper
(LightGBM over cross-encoder outputs).

## Their method [ZR]: text only
The 2022 competition data had no images. ESCI ships title, description, bullets, brand and color, and images only
arrived in 2024 through SQID. So neither ZR nor [www] could use them. Their stand-ins for "what the product looks like":

| Team | Technique | What it captured |
|---|---|---|
| [ZR] | brand and color **ID embeddings** (128-d each) concatenated to [CLS] in every member's head; `RobertaWithSampleWeight_Bag` adds char 3-gram bags + locale (head input `hidden + 2·bc_dim + 3·64 + 8`) | non-text side features beside the transformer |
| [ZR] | the `color` field as text inside the product text | the one visual attribute the catalog names |
| [www] | color and brand moved to the front: `color: … brand: … description: …` | the same, given more weight |

## Their weaknesses
| # | Weakness | Why it matters |
|---|---|---|
| 1 | Blind to appearance: pattern, shape, material and style exist only if the seller wrote them down | queries like "floral midi dress" or "matte black faucet" depend on exactly that |
| 2 | The color signal is only as good as the `color` field, which is often empty or a vendor code (Phase 2 reports the empty rate) | the one visual attribute they had is unreliable |
| 3 | Their side-feature slot exists but carries only IDs and n-grams | the architecture already has a place for an image vector that they couldn't fill |

## Our target
- On dev, a significant gain (CI > 0) over **our best text-only system**, and therefore over ZR.
- The **visual-attribute slice** (color/pattern/material words in the query) gains the most.
- The **no-image slice** must not lose: the text path still works when a photo is missing.
- A tie or a loss is a valid result and is recorded as such.

## Where images exist
- dev/test pairs: **95.2%** imaged. Train pairs: **20.8%** (≈ 290k of 1.39M).
- Image *training* (variant C) uses those ≈ 290k pairs plus the pairs without an image.
- Combiners on frozen models (variant A) are fitted on (a) the imaged **train** pairs, using the out-of-fold Phase 4
  scores, or (b) dev with cross-validation. (a) keeps dev clean and comes first; (b) is the fallback if train-pair
  scores turn out too unlike dev's.

## Our proposal: three variants, cheapest first
| Variant | What changes vs ZR | Fixes | Cost |
|---|---|---|---|
| **A. Late fusion** | a small combiner merges the text reranker's outputs with CLIP query↔image similarity | 1, 2 | CPU minutes |
| **B. Caption field** | an image caption (Phase 2) becomes one more field: `title · brand · color · caption · bullets · desc` | 1, 2 | one Phase 4 training run |
| **C. Image embedding in their side-feature slot** | `concat([CLS], side features, Linear(768→128)(clip_image_emb))` → dense → head; a learned "no image" vector when the photo is missing; fine-tuned from the Phase 4 winner | 3 | one fine-tune run |

### Variant A in detail
**Features per (query, product) pair**
| Group | Features |
|---|---|
| text reranker | P(E), P(S), P(C), P(I); expected gain; regression score if there is one |
| image | CLIP cosine(query text, product image); `has_image` |
| text similarity | CLIP cosine(query text, product title) |
| within the query's candidate list | rank of each score above; gap to the query's best; z-score within the query |
| simple | title length, query length |

The within-query features matter because ranking is decided within a query: an image similarity of 0.30 is high for
one query and low for another.

**Training procedure (the same for every combiner)**
1. Build the table (one row per pair) on the fitting set, with group = query_id.
2. Split by query into 5 folds (`GroupKFold`), so all pairs of a query stay together.
3. For each fold, fit on the other 4 and predict it. Every pair ends up with an **out-of-fold** score from a model
   that never saw its query.
4. Score nDCG on the out-of-fold scores. When fitting on dev (option b), this out-of-fold number **is** the reported
   dev number. In-fold scores would be optimistic.
5. Tree hyperparameters: a small fixed grid. Early stopping uses an inner split of the 4 training folds, never the
   held-out fold.
6. Overfitting check: report in-fold vs out-of-fold nDCG.
7. Refit on the whole fitting set; that model scores final test once and is exported for serving.

**Combiner ladder** (each must beat the previous one)
| Step | Combiner | Setup |
|---|---|---|
| A0 | weighted sum | `expected_gain + w · clip_image_cos`, one weight (SQID's fusion, the minimum) |
| A1 | logistic regression | multinomial over E/S/C/I on standardized features → expected gain `Σ gain·p` |
| A2 | LightGBM LambdaRank | `objective=lambdarank`, `group=query`, labels I0 C1 S2 E3, `label_gain=[0, 1, 10, 100]`; `num_leaves` 15–31, `min_data_in_leaf` 50, lr 0.05, ≤ 500 rounds + early stopping |
| A3 | XGBoost ranker | `rank:ndcg` (also `rank:pairwise`), `qid=query`, labels 0–3, also `ndcg_exp_gain=False`; `max_depth` 4–6, `eta` 0.05, ≤ 500 rounds + early stopping |

A2 and A3 run only if A1 beats A0. If a linear model finds no signal in the image features, a tree model on
40k–290k rows is more likely to overfit than to find one. All combiners are scored with ESCI gains, whatever their
objective used internally.

## Eval
- Paired gain vs the Phase 4 winner and vs ZR on dev, overall and per slice: **visual-attribute queries**,
  **products without an image**, query-length buckets.
- Variant A: out-of-fold nDCG for A0–A3, the in-fold vs out-of-fold gap, and feature importance.
- The winning variant goes to final test once, becomes the reranker for later phases, and is an ensemble candidate
  in [6.md](6.md).

## Output
`mmsearch/fusion.py` (feature table, GroupKFold loop, A0–A3), the image block in `mmsearch/model.py` (variant C),
`scripts/p5_multimodal.py`, `runs/p5/`.
