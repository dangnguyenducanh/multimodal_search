# Phase 10: Frontend (React + Vite + TypeScript)

**Goal:** a small shop-style demo that shows **what we improved over the baseline**: ZR vs ours on known queries,
text-only vs multimodal, and the recommendation rows.
**Baseline:** none to show. ZR has no interface, so the demo puts their saved Phase 0 rankings next to ours
([9.md](9.md) `/api/compare`). **Sources:** layout modelled on the Anon e-commerce template; structure follows the
Zalo project's `docs/05-frontend.md`.
**Current state:** the Home / Search / Product pages are live without a reranker; see [demo-handoff.md](demo-handoff.md).
The Compare page and the photo page are not built yet.

## Their method [ZR]
No interface. The output is a ranking file per query.

## Their weaknesses
| # | Weakness | Why it matters |
|---|---|---|
| 1 | A ranking file can't show *why* one system beats another | the improvement over the baseline has to be visible to a reader, not only a number in a table |
| 2 | No way to try a new query or a photo | the system can't be explored |

## Our target
- Every number on the page comes from `/api/models` or `/api/compare` (that is, from RESULTS files) and is never
  hard-coded.
- The "Baseline vs ours" view shows the ZR and our ranking side by side for any known dev/test query, including
  queries where **we lose** (shown, not hidden).
- The Playwright smoke test below passes, and the page is interactive in < 2 s on a cold load.

## Our proposal
### Design source: Anon template, rebuilt rather than copied
`codewithsadee/anon-ecommerce-website` (plain HTML/CSS/JS) has **no license**, so we copy **no files, CSS or images**
from it and rebuild its layout in our own components:

| Anon element | Our version |
|---|---|
| header with a wide search bar | `Header`: search bar + camera button (photo search) |
| product card | `ProductCard`: image, brand tag, title, **model badge** (E/S/C/I + score), **human-label badge** when known |
| "New arrivals / Trending" side lists | product page rows: **Alternatives**, **Goes with** |
| category sidebar, banner slider | dropped (ESCI has no category tree); replaced by the example-query strip |

Visual rules: white background, one accent color, a responsive card grid (4 → 2 → 1 columns), and images with
`object-fit: contain` on a light-grey box, since Amazon packshots vary in shape.

### Routes
```text
/                     HomePage        search bar, example-query chips (/api/examples), model footer
/search?q=&mode=      SearchPage      results grid, Multimodal ↔ Text-only toggle, timings
/compare?q=           ComparePage     ZR baseline vs ours, side by side, for a known dev/test query
/product/:id          ProductPage     details, Alternatives row, Goes-with row
/photo                PhotoSearchPage upload → results, marked "no ground truth (demo only)"
*                     NotFoundPage
```
Search state lives in the URL (`q`, `mode`), so results are shareable and the back button works.

### Screens
| Screen | Behaviour |
|---|---|
| **Home** | big search bar; 20 example chips tagged "we gained" / "we lost" / "random"; footer with each model's dev nDCG ± CI and ms per query (ZR, ours text, ours multimodal) |
| **Search** | grid of cards. The mode toggle refetches with `mode=text`, and cards whose rank changed show `↑3` / `↓2`. For a known query, a banner offers "Compare with baseline" and each card shows its human label |
| **Compare** | two columns, ZR's order and ours, over the same judged products: human-label badges, lines linking each product's two positions, and both nDCGs with their difference |
| **Product** | image, title, brand, color, bullets; Alternatives (P(S)) and Goes-with (P(C)) rows |
| **Photo search** | resize in the browser (canvas → JPEG ≤ 1024 px) → `POST /api/search/image`; same grid; "demo only" note |
| **Errors** | `ErrorBanner` shows the backend's `error.message`; empty results → `EmptyState` with example queries |

### Structure and rules
```text
web/src/
├── main.tsx, router.tsx
├── api/client.ts     getJson<T>(), postForm<T>(), isApiError() guard
├── types/api.ts      mirrors 9.md shapes (optionally generated from /openapi.json with openapi-typescript)
├── components/       Header, SearchBar, PhotoButton, ProductCard, ResultsGrid, ModeToggle, CompareColumns,
│                     ProductRow, LabelBadge, TimingsBar, ModelFooter, EmptyState, ErrorBanner
├── pages/            HomePage, SearchPage, ComparePage, ProductPage, PhotoSearchPage, NotFoundPage
└── styles/           tokens.css, base.css, components.css
```
- TypeScript `strict` + `noUncheckedIndexedAccess`; `tsc --noEmit` runs before `vite build`.
- State: URL params for query and mode; a ~30-line `useApi<T>(url)` hook (`AbortController` cancels stale
  searches); local `useState` for the upload preview. No Redux, no context providers.
- Accessibility basics: every icon button has an `aria-label`, badges carry text rather than color alone, and
  images use the title as `alt`.
- `npm run dev` (Vite on 5173, proxied to 8000) · `npm run build` → `web/dist`, served by FastAPI at `/`.

## Eval
| Check | Pass condition |
|---|---|
| types | `tsc --noEmit` clean; `types/api.ts` matches `/openapi.json` |
| smoke test | Playwright: Home → each example chip renders results → toggle mode, and order changes on "we gained" queries → open Compare, where both columns render with the RESULTS nDCGs → open a product, where both rows render → a photo upload returns results |
| honesty | numbers come from `/api/models` and `/api/compare`, never hard-coded; "we lost" examples are listed |
| speed | interactive < 2 s on a cold load; search round trip within the backend budget |
