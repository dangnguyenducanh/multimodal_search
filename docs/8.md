# Phase 8: Recommendations (item-to-item)

**Goal:** "Alternatives" and "Goes with" rows for any product, using the same models.
**Baseline:** the ZR run from [0.md](0.md): its 4-class members give P(S) and P(C) for every judged pair.
**Sources:** ESCI's Substitute and Complement labels · KDD Cup Task 3 (substitute identification): 1st place
day-day-up 0.8790 micro-F1, [ZR] 8th with 0.8686 (`code_task3/`).

## Why item-to-item
ESCI has no users, sessions or purchase histories, so personalized recommendation can't be trained or evaluated.
What it does have: for each query, which products are **Substitutes** (alternatives) and which are **Complements** (goes with).

## Their method [ZR]
- Task 3: a separate 4-class-style model trained to flag **Substitute vs not**, for a (query, product) pair
  (`code_task3/run_glue_no_trainer.py`).
- Nothing product-to-product, and no Complement model.

## Their weaknesses
| # | Weakness | Why it matters |
|---|---|---|
| 1 | Substitutes are judged against a **query**, never against a product the user is looking at | a product page has no query, only the viewed product |
| 2 | A separate model per task (Task 3 apart from Task 1) | more models to train and serve for one signal the Task 1 classifier already produces (P(S)) |
| 3 | Complements are ignored | "goes with" is half of what a product page needs |
| 4 | Text only | the look of an alternative (same style, different brand) is ignored |

## Our target
- On the proxy evaluation below, MRR and Recall@5 above all three baselines (random, text similarity, image
  similarity) with CI > 0, for both rows.
- Task 3 substitute F1 on dev from our reranker's P(S), **at least ZR's** (their c1–c3 P(S) on the same dev pairs,
  from Phase 0), without a separate Task 3 model.

## Our proposal
1. **Candidates:** the viewed product's title is the query → Phase 7 retrieval (top 100).
2. **Scores** from the Phase 4/5 reranker's class probabilities, one model for search and both rows:
   - Alternatives: `P(S)`, plus image similarity to the viewed product (fusion weight fit on dev)
   - Goes with: `P(C)`
3. Remove the viewed product and near-duplicates (same title after cleaning); return the top 10.

## Eval (proxy, on dev queries)
Setup: for a query with ≥ 1 Exact and ≥ 1 Substitute product (7,736 test queries) or ≥ 1 Complement (2,294), take an
Exact product as the "viewed" product and rank the query's *other judged* products.

| Task | Positives | Metrics |
|---|---|---|
| Alternatives | Substitute-labelled products | MRR, Recall@5 |
| Goes with | Complement-labelled products | MRR, Recall@5 (fewer queries → wider CIs) |
| Substitute identification | S vs not-S on all judged pairs | micro-F1, vs ZR's from Phase 0 |

Baselines: random order · text similarity to the viewed product (bi-encoder cosine) · image similarity (CLIP) ·
ZR's P(S) / P(C) from Phase 0's saved member scores.

**Caveat (also stated in RESULTS.md):** S and C labels describe a product's relation to the **query**, not to the
viewed product, so this evaluation is an approximation.
